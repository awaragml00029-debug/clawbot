## memory_search scope denied 修复

- 问题：`memory_search` 返回 `disabled=true`，日志显示 `qmd search denied by scope (channel=unknown, chatType=unknown, session=<none>)`
- 根因：`DEFAULT_QMD_SCOPE` 是 `{ default: "deny", rules: [{ action: "allow", match: { chatType: "direct" } }] }`，session key 未传入导致 chatType 解析为 unknown，触发 deny
- 修复：在 `openclaw.json` 的 `memory.qmd.scope` 中设置 `{ "default": "allow" }` 覆盖默认 scope
- 位置：`reply-Bm8VrLQh.js` 行 55583（DEFAULT_QMD_SCOPE）、行 55752（scope 注入）

## 混合搜索状态

- 当前 `searchMode: "search"`（纯 BM25），不是混合搜索
- 混合搜索（`searchMode: "query"`）需要 embedding provider（OpenAI/Gemini/Voyage/Ollama）
- 当前环境无可用 embedding provider（node-llama-cpp 不可用，无远程 API key）
- 结论：混合搜索在当前环境不可用（见下）

## QMD 混合搜索不可用原因 (02:43 EDT)

- qmd 自带三种搜索：`search`（BM25）、`vsearch`（向量）、`query`（混合 BM25+向量+重排序）
- qmd 已有 4928 个向量嵌入，372 个 pending
- `vsearch` 和 `query` 内部依赖 `node-llama-cpp` 做 embedding 和 query expansion
- 当前系统：`node-llama-cpp` prebuilt binary 与 linux x64 Vulkan 不兼容，fallback 到 CPU
- CPU fallback 太慢，`vsearch` 超时（15秒 timeout 124），`query` 完全卡住
- 结论：保持 `searchMode: "search"`（纯 BM25），对 1647 个文件足够
- 如需混合搜索：需要 GPU 驱动支持或改用 Ollama 做 embedding
